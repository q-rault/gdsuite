## What this page is for

This page gets a machine from zero to a working `gdsuite` project setup.

## When you should use this

Use this page when you are setting up a new development machine or when a project has not been bootstrapped with `gdsuite` yet.

## What you need before starting

- Rust installed so `cargo` is available
- Git installed when a tool source uses `git:...`
- A Godot 4 executable installed locally
- A Godot project directory you can work in

## Step-by-step instructions

1. Install the `gdsuite` CLI.

```bash
cargo install gdsuite
```

2. Move to your Godot project root.

```bash
cd path/to/your-project
```

3. Bootstrap the project-owned suite state.

```bash
gdsuite init
```

That now defaults to readable scoped logs such as:

```text
[gdsuite:init] step  installing local toolchain
[gdsuite:init] ok    initialization complete
```

4. Verify what the suite resolved.

```bash
gdsuite doctor
```

If Godot is in a non-standard location, pass `--godot-exe`, set `GODOT_EXE`, or configure it in `gdsuite.toml` before rerunning `doctor`.
Use `gdsuite doctor --output plain` for stable shell parsing or `gdsuite doctor --output json` for structured integrations.

## What success looks like

Success means:

- `.gdsuite/` exists in the project and is listed in `.gitignore`, along with other generated folders
- `gdsuite.toml` exists
- `gdsuite doctor` prints resolved paths and ends with `[gdsuite:doctor] status ok`

## Common mistakes

- Installing `gdsuite` globally but never running `gdsuite init` inside the project
- Assuming Godot discovery will work if the executable has a custom name or location
- Keeping a tool's settings both in its own file (`gdtest.toml`, `gdhealth.toml`, `gdtidy.toml`) and in its `gdsuite.toml` section: the section wins and the file is ignored
