title: Install

Installing GDSuite takes two steps: put the `gdsuite` program on your
computer once, then add GDSuite to each Godot project you want it to watch.

You only install GDSuite: the formatter, linter, type checker, test runner
and code health tool are built into the `gdsuite` program, so there is
nothing else to download (see [Under the hood](/under-the-hood) if you are
curious).

<Callout title="Coming soon: the Godot Asset Store">

GDSuite will be installable from the Godot Asset Store, inside the editor,
with no terminal needed. Until then, use one of the two ways below.

</Callout>

## 1. Get the `gdsuite` program

You need [Godot](https://godotengine.org/download) 4.5 or newer.

<Tabs items={['Download (no Rust needed)', 'cargo (for Rust users)']}>

<Tab value="Download (no Rust needed)">

Download the archive for your computer from the
[latest GitHub release](https://github.com/q-rault/gdsuite/releases/latest):

| Your computer | File to download |
| --- | --- |
| Windows | `gdsuite-v<version>-x86_64-pc-windows-msvc.zip` |
| macOS, Apple Silicon (M1 and later) | `gdsuite-v<version>-aarch64-apple-darwin.tar.gz` |
| macOS, Intel | `gdsuite-v<version>-x86_64-apple-darwin.tar.gz` |
| Linux | `gdsuite-v<version>-x86_64-unknown-linux-musl.tar.gz` |

Unpack it and put the `gdsuite` program (`gdsuite.exe` on Windows) in a folder
on your `PATH`, so a terminal finds it from anywhere:

- **Windows**: create a folder such as `C:\Tools`, put `gdsuite.exe` in it,
  then search the Start menu for "Edit environment variables for your
  account", select `Path`, click Edit, then New, and add `C:\Tools`.
- **macOS and Linux**: move it to `~/.local/bin` (create the folder if needed)
  and make sure that folder is on your `PATH`.

</Tab>

<Tab value="cargo (for Rust users)">

With [Rust](https://rustup.rs) 1.96 or newer:

```bash
cargo install gdsuite
```

</Tab>

</Tabs>

Open a **new** terminal and check it works:

```bash
gdsuite --version
```

## 2. Add GDSuite to your project

In a terminal, go to your project's folder (the one with `project.godot`) and
run `gdsuite init`:

```bash
cd path/to/my-game
gdsuite init
```

It takes a few seconds, works offline, and prints what it does:

```text
[gdsuite:init] step  resolving project setup
[gdsuite:init] step  resolving Godot executable
[gdsuite:init] step  writing gdsuite config
[gdsuite:init] step  installing local toolchain
[gdsuite:init] step  saving tool manifest
[gdsuite:init] step  installing gdtest addons
[gdsuite:init] step  refreshing Godot class cache
[gdsuite:init] step  verifying installed tools
[gdsuite:init] step  recording installation state
[gdsuite:init] ok    initialization complete
```

Your project now has:

| What | Why | Commit it? |
| --- | --- | --- |
| `gdsuite.toml` | GDSuite's settings | Yes |
| `addons/gdtest/` | Lets your tests run inside Godot | Yes |
| `addons/gdtest_editor/` | The test panel for the Godot editor | Yes |
| `.gdsuite/` | What GDSuite keeps for this project on this computer | No (added to `.gitignore`) |

### If Godot isn't found

GDSuite looks for Godot in the usual places. If yours has another name or
lives somewhere else, tell `init` where it is:

```bash
gdsuite init --godot-exe "C:/Tools/Godot_v4.7-stable_win64.exe"
```

GDSuite remembers it for this project, on this computer (the path is not
written in `gdsuite.toml`, so teammates keep their own). You can also set the
`GODOT_EXE` environment variable once for all your projects.

## 3. Check everything is ready

```bash
gdsuite doctor
```

It lists Godot and each tool built into GDSuite, with its version, and ends
with:

```text
[gdsuite:doctor] status ok
```

If it ends with `status error`, each line above says what is missing and how
to fix it. See [Troubleshooting](/troubleshooting).

## Updating GDSuite

The tools are part of the `gdsuite` program, so updating GDSuite updates
everything. Get the new `gdsuite` the way you got the first one: download it
again, or run `cargo install gdsuite` again.

Projects set up by GDSuite 0.4 or earlier downloaded their tools into
`.gdsuite/`, and may have their versions written in `gdsuite.toml`. Run this
once in each of them:

```bash
gdsuite update
```

It removes the old versions from `gdsuite.toml` and the downloaded tools from
`.gdsuite/`. Until you run it, commands warn that the project still uses the
downloaded tools.
