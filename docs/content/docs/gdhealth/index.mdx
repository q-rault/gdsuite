`gdhealth` is the architecture health engine inside the suite story. For normal workflows, start with `gdsuite health`. That keeps the command naming, report handling, and config overlay behavior consistent with the rest of the suite.

## Stay in `gdsuite health` when

- you want the normal suite health run
- you want a suite report with `--report json`
- you care about CI-friendly workflow framing first

## Go deeper into direct gdhealth docs when

- you need report interpretation details
- you need configuration depth for groups or dependency policy
- you are doing an architecture review rather than a normal suite pass

Use `gdlint` guidance for per-file and per-function metric ownership.
