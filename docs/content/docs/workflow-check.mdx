## What this page is for

This page explains the purpose of `gdsuite check`, the suite's default local validation command.

## When you should use this

Use this page when you want fast feedback during normal development or when you need to understand why `check` behaves differently from `test` and `health`.

## What you need before starting

- Resolved local tooling from `gdsuite init` or `gdsuite setup`
- Optional: `gdsuite.toml` if you want to override the built-in suite defaults

## Step-by-step instructions

1. Run the default local gate.

```bash
gdsuite check
```

2. Use `--fix` when you want the suite to apply safe automatic cleanup before it verifies the remaining phases.

```bash
gdsuite check --fix
```

## What success looks like

A successful `check` run means the fixed fast pipeline passed: formatting, linting, and GDScript type checking. `check` is sequential and fail-fast, so later phases run only when earlier phases succeed. If `gdsuite.toml` is missing, `check` still runs using built-in defaults. The local toolchain still has to exist under `.gdsuite/state/manifest.json`.

## Common mistakes

- Assuming `gdsuite check` runs tests or health checks — it does not; use `gdsuite test` and `gdsuite health` separately
- Expecting `check` to change meaning based on profiles or CI context
- Expecting report-generation options to be part of the core `check` contract
