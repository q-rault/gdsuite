`gdtest` is the test engine inside the suite story. For most workflows, start with `gdsuite test`. That gives you the suite-owned entrypoint, reporting, and workflow framing.

## Stay in `gdsuite test` when

- you want the normal suite path for behavior validation
- you want a suite report with `--report json`
- you do not need product-specific flags yet

## Go deeper into direct gdtest docs when

- you need harness details
- you need filtering, mocking, scene runner, or snapshot semantics
- you are working directly on the test system rather than the suite workflow
