---
title: Welcome to GDSuite
description: Keep a Godot project tidy, correct and easy to change, with one tool.
---

GDSuite watches over your GDScript while you build your game. It tidies the
layout of your scripts, points at likely mistakes, finds errors in scripts you
haven't opened, runs your tests, and tells you which scripts are getting too
big to change safely.

You install one thing, GDSuite, and run one command to check everything:

```bash
gdsuite check
```

## What it does for you

<Cards>
  <Card title="Formatting" href="/formatting">
    Spaces, indentation and blank lines laid out the same way in every script,
    following Godot's style guide. It never changes what your code does.
  </Card>
  <Card title="Linting" href="/linting">
    Points at code that works but is probably a mistake, or hard to read: a
    variable you never use, a function that is far too long.
  </Card>
  <Card title="Type checking" href="/type-checking">
    Finds the errors Godot would show you, in every script and scene of the
    project, including the ones you haven't opened today.
  </Card>
  <Card title="Testing" href="/testing">
    Small scripts that play a piece of your game and check the result, so you
    know a change didn't break something that used to work.
  </Card>
  <Card title="Code health" href="/code-health">
    Shows which scripts have grown too big or too tangled, before they become
    painful to change.
  </Card>
  <Card title="Check everything" href="/check">
    One command runs them all, the same way on your machine and on a server.
  </Card>
</Cards>

## A taste

Here is what formatting does to a script written in a hurry:

<BeforeAfter>

```gdscript
extends Node

const MAX_HEALTH=100
var health:int=MAX_HEALTH

func take_damage(amount:int)->void:
    health=max(health-amount,0)
    if health==0 :
        died.emit()
```

```gdscript
extends Node

const MAX_HEALTH = 100
var health: int = MAX_HEALTH


func take_damage(amount: int) -> void:
	health = max(health - amount, 0)
	if health == 0:
		died.emit()
```

</BeforeAfter>

And here is what a check finds in a small project:

```text
player/player.gd:11:1: warning[class-definitions-order]: Definition out of order in global scope: `signals` must come before `others`
hud.gd:10: error[missing-resource]: "res://levels/level_2.tscn" does not exist
```

The second line is a scene that was renamed or deleted: the game would only
fail when the player reaches the exit.

## Do I need to be a programmer?

No. If you write GDScript in the Godot editor, GDSuite is for you. Every page
here starts with what a feature does and why it helps, before any command.
GDSuite runs from a terminal today, and its tests already have a panel in the
Godot editor; the rest of its features are coming to the editor too.
