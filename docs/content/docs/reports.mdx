## What this page is for

This page explains what the suite reports are, what they are not, and how they relate to direct `gdtest` and `gdhealth` outputs.

## When you should use this

Use this page when you are wiring automation, reviewing CI artifacts, or deciding whether to consume suite JSON or raw product output.

## What you need before starting

- A project that has already run one or more commands with `--report json`
- Basic understanding of `check`, `test`, and `health`

## Step-by-step instructions

1. Generate suite report artifacts.

```bash
gdsuite check --report json
gdsuite test --report json
gdsuite health --report json
```

2. Read the latest suite report.

```bash
gdsuite report latest
```

3. Aggregate a CI summary when separate step artifacts already exist.

```bash
gdsuite report ci
```

## What success looks like

Success means you can retrieve stable suite envelopes from `reports/gdsuite/` while still keeping delegated artifacts such as the raw `gdhealth` bundle when present.

## Common mistakes

- Assuming every delegated tool already emits the same suite JSON format
- Confusing `reports/gdsuite/*.json` with raw `gdhealth` bundle files
- Forgetting that lint JSON is suite-shaped: gdsuite turns gdtidy's report into `findings` and `skipped`
