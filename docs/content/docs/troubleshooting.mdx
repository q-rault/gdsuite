## Run `doctor` first

If the suite feels broken, start with:

```bash
gdsuite doctor
```

That prints resolved paths, config locations, setup state, and warnings about product config drift.

When all tools are installed, pretty output ends with `[gdsuite:doctor] status ok`:

```
[gdsuite:doctor] info  project root  /your/project
[gdsuite:doctor] info  config        /your/project/gdsuite.toml
[gdsuite:doctor] info  godot         /usr/local/bin/godot
[gdsuite:doctor] info  version       4.7.stable.official
[gdsuite:doctor] info  python        /your/project/.gdsuite/python/bin/python
[gdsuite:doctor] info  version       Python 3.12.3
[gdsuite:doctor] status ok
```

When tools are missing, each missing entry says exactly what to run to fix it, and `[gdsuite:doctor] status error` appears at the end:

```
[gdsuite:doctor] warn  godot not found; install Godot and add to PATH, or set GODOT_EXE, or set project.godot_exe in gdsuite.toml
[gdsuite:doctor] warn  python not found; run `gdsuite setup` to install the toolchain
[gdsuite:doctor] warn  gdformat not found; run `gdsuite setup` to install the toolchain
[gdsuite:doctor] warn  gdlint not found; run `gdsuite setup` to install the toolchain
[gdsuite:doctor] warn  gdtest not found; run `gdsuite setup` to install the toolchain
[gdsuite:doctor] warn  gdhealth not found; run `gdsuite setup` to install the toolchain
[gdsuite:doctor] status error
error: missing tools: godot, python, gdformat, gdlint, gdtest, gdhealth; run `gdsuite setup` to install the local toolchain
```

Use `gdsuite doctor --output plain` when you want stable `key=value` lines for shell scripts, or `gdsuite doctor --output json` for a structured report.

## Common failure modes

### `run gdsuite init first`

The project was never bootstrapped. Run:

```bash
gdsuite init
```

### Product config drift warnings

`doctor` warns when `gdtest.toml` or `gdhealth.toml` drift from suite-owned invariants. The preferred repair path is:

```bash
gdsuite migrate
```

Use `gdsuite setup --sync-product-configs` only when you specifically want the lower-level repair/bootstrap flow.

### CI aggregation fails

`gdsuite report ci` needs existing JSON artifacts from:

- `gdsuite check --report json`
- `gdsuite test --report json`
- `gdsuite health --report json`

### Health seems to ignore config exclusions

Remember that `gdsuite health` writes and uses a suite overlay for `gdhealth.toml` so suite-generated state does not leak into analysis.
