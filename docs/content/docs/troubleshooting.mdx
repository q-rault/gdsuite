## Run `doctor` first

If the suite feels broken, start with:

```bash
gdsuite doctor
```

That prints resolved paths, config locations, setup state, and warnings about product config drift.

When all tools are installed, output ends with `status=ok`:

```
project_root=/your/project
config=/your/project/gdsuite.toml
manifest=/your/project/.gdsuite/state/manifest.json
godot=/usr/local/bin/godot
godot_version=4.7.stable.official
python=/your/project/.gdsuite/python/bin/python
python_version=Python 3.12.3
gdformat=/your/project/.gdsuite/python/bin/gdformat
gdformat_version=gdformat 4.5.0
gdlint=/your/project/.gdsuite/python/bin/gdlint
gdlint_version=gdlint 4.5.0
gdtest=/your/project/.gdsuite/tools/gdtest/bin/gdtest
gdtest_version=gdtest 0.1.0
gdhealth=/your/project/.gdsuite/tools/gdhealth/bin/gdhealth
gdhealth_version=gdhealth 0.1.0
status=ok
```

When tools are missing, each missing entry says exactly what to run to fix it, and `status=error` appears at the end:

```
project_root=/your/project
config=/your/project/gdsuite.toml
manifest=/your/project/.gdsuite/state/manifest.json
godot=not found; install Godot and add to PATH, or set GODOT_EXE, or set project.godot_exe in gdsuite.toml
python=not found; run `gdsuite setup` to install the toolchain
gdformat=not found; run `gdsuite setup` to install the toolchain
gdlint=not found; run `gdsuite setup` to install the toolchain
gdtest=not found; run `gdsuite setup` to install the toolchain
gdhealth=not found; run `gdsuite setup` to install the toolchain
status=error
error: missing tools: godot, python, gdformat, gdlint, gdtest, gdhealth; run `gdsuite setup` to install the local toolchain
```

## Common failure modes

### `run gdsuite init first`

The project was never bootstrapped. Run:

```bash
gdsuite init
```

### Product config drift warnings

`doctor` warns when `gdtest.toml` or `gdhealth.toml` drift from suite-owned invariants. The preferred repair path is:

```bash
gdsuite migrate
```

Use `gdsuite setup --sync-product-configs` only when you specifically want the lower-level repair/bootstrap flow.

### CI aggregation fails

`gdsuite report ci` needs existing JSON artifacts from:

- `gdsuite check --report json`
- `gdsuite test --report json`
- `gdsuite health --report json`

### Health seems to ignore config exclusions

Remember that `gdsuite health` writes and uses a suite overlay for `gdhealth.toml` so suite-generated state does not leak into analysis.
