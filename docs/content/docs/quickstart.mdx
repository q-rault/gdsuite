## What this page is for

This page gets you to the first successful `gdsuite` workflow run without assuming prior knowledge of Godot headless tooling or delegated product boundaries.

## When you should use this

Use this page right after installation, or when you need a fast reminder of the suite's normal flow.

## What you need before starting

- A Godot project root
- `gdsuite` installed
- `gdsuite init` already run in the project

## Step-by-step instructions

1. Run the fast local gate.

```bash
gdsuite check
```

2. Run tests when behavior changed.

```bash
gdsuite test
```

3. Run architecture health when the change affects structure, layering, or CI policy.

```bash
gdsuite health
```

4. If you are shaping CI artifacts, emit JSON reports explicitly.

```bash
gdsuite check --report json
gdsuite test --report json
gdsuite health --report json
gdsuite report ci
```

## What success looks like

You should end with:

- a successful `check` run for the local gate
- delegated `test` and `health` runs succeeding when the project is ready
- `reports/gdsuite/check.json`, `test.json`, `health.json`, and `ci.json` present when you used JSON reporting

## Common mistakes

- Expecting a standalone `gdsuite ci` command to exist
- Running `test` or `health` before the project was bootstrapped with `gdsuite init`
- Treating `gdsuite check` as if it always includes tests and health checks
