By default, a gdsuite project has one configuration file: `gdsuite.toml`. It
holds gdsuite's own settings and, when you need them, a section per tool:

| Section | Tool | Same keys as |
|---|---|---|
| `[test]` | gdtest | `gdtest.toml` |
| `[health]` | gdhealth | `gdhealth.toml` (`[groups]` becomes `[health.groups]`) |
| `[lint]`, `[fmt]` | gdtidy | `gdtidy.toml` |

Each tool reads its own section itself, so the settings apply however the tool
is started: through `gdsuite`, from a terminal (`gdtest`, `gdtidy lint`), or
from an editor (the gdtest panel in Godot).

`gdsuite init` and `gdsuite setup` write only `gdsuite.toml`, with no tool
settings: the tools' defaults apply until you add a section.

## Tool config files

`gdtest.toml`, `gdhealth.toml` and `gdtidy.toml` keep working, for projects
that use a tool without gdsuite or prefer one file per tool. A tool reads its
own file when `gdsuite.toml` has no section for it.

**Keep each tool's settings in one file.** When `gdsuite.toml` has a tool's
section, that tool ignores its own file next to it and prints a warning. The
two are never merged, so a setting in the ignored file has no effect.
`gdsuite migrate` moves a tool file into `gdsuite.toml` for you.
