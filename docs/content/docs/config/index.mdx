title: Config Overview
description: Understand which config belongs to the suite and when delegated product configs still matter.
---

`gdsuite.toml` is the suite-owned top-level contract. It is the normal config
surface for `gdsuite` workflows.

`gdtest.toml` and `gdhealth.toml` are product-owned files for users who run
`gdtest` or `gdhealth` directly outside of `gdsuite`. They are not part of the
normal `gdsuite` runtime contract.

## Ownership split

- Suite-owned: the workflow contract in `gdsuite.toml`, suite report paths,
  local toolchain state, and the delegated-tool settings that matter to normal
  `gdsuite` workflows
- Product-owned: direct `gdtest` harness and runtime knobs, direct `gdhealth`
  groups and dependency policy, and deeper product-only behavior for users who
  run those tools separately

`gdtidy lint` owns per-file and per-function maintainability metrics. `gdhealth` stays focused on architecture and policy.

## What the suite reads

- `gdsuite init` creates `gdsuite.toml` and may import settings from existing
  `gdtest.toml` or `gdhealth.toml`
- normal runtime commands read `gdsuite.toml` and suite-managed state
- `gdsuite` does not depend on delegated product configs during normal runtime
