---
title: gdhealth.toml compatibility
description: When gdhealth.toml is still useful and how that stays separate from the suite contract.
---

`gdhealth.toml` remains a normal `gdhealth` config file. For `gdsuite`, it is
now a compatibility file rather than part of the normal suite runtime contract.

## What `gdsuite` uses instead

`gdsuite` should read `gdsuite.toml` for suite workflows, including the
`gdhealth`-related settings that matter to `gdsuite health`.

## When `gdhealth.toml` still matters

- when you run `gdhealth` directly
- when `gdsuite init` imports settings from an older repository

## What `gdsuite` does not assume

- it does not require `gdhealth.toml` to exist
- it does not keep `gdhealth.toml` aligned with `gdsuite.toml`
- it does not use delegated-config drift as part of the target architecture

## Ownership boundary

`gdhealth` is the architecture and policy layer. `gdtidy lint` owns per-file and per-function maintainability metrics.

Treat local metric thresholds that overlap with `gdtidy lint` as compatibility-era product detail, not as the preferred long-term ownership model for suite documentation.
