---
title: gdhealth.toml compatibility
description: Which gdhealth config areas stay product-owned and which ones the suite overlays or synchronizes.
---

`gdhealth.toml` remains a normal `gdhealth` config file. The suite keeps a narrow set of discovery and exclusion invariants aligned so health runs behave consistently in suite workflows.

## Suite-owned expectations

- suite-aligned discovery include and exclude rules
- overlays that keep `.gdsuite/**` generated state out of analysis

## Product-owned areas

- groups
- policy rules
- direct architecture-specific tuning

## Ownership boundary

`gdhealth` is the architecture and policy layer. `gdlint` owns per-file and per-function maintainability metrics.

Treat local metric thresholds that overlap with `gdlint` as compatibility-era product detail, not as the preferred long-term ownership model for suite documentation.
