---
title: Product Config Generation
description: How delegated product configs relate to the suite-first model and when they still matter.
---

The suite-first model does not depend on generated `gdtest.toml` or
`gdhealth.toml` files.

`gdsuite` should use `gdsuite.toml` for normal operation. Delegated product
configs remain relevant only for direct `gdtest` or `gdhealth` CLI usage, or
as import inputs when adopting an older repository.

## What `init` does

- writes the top-level `gdsuite.toml`
- detects existing `gdtest.toml` or `gdhealth.toml`
- imports relevant settings from those files into `gdsuite.toml`
- leaves delegated product configs untouched after import

## What the suite does not do

- it does not create `gdtest.toml`
- it does not create `gdhealth.toml`
- it does not synchronize delegated product configs with `gdsuite.toml`
- it does not treat drift between delegated product configs and `gdsuite.toml`
  as part of the intended architecture

## When delegated product configs still matter

- keep `gdtest.toml` only if you run `gdtest` directly
- keep `gdhealth.toml` only if you run `gdhealth` directly
- otherwise, prefer a repository shape centered on `gdsuite.toml`
