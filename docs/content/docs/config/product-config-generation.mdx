---
title: Tool config files
description: What init, setup and migrate write, and how gdtest.toml, gdhealth.toml and gdtidy.toml fit in.
---

## What `init` and `setup` write

- `gdsuite.toml`, with gdsuite's own sections, if it is missing.
- Nothing for the tools: no `gdtest.toml`, `gdhealth.toml` or `gdtidy.toml`,
  and no tool section. The tools' defaults apply until you add a section.
- One exception: gdtidy reads neither `gdlintrc` nor `gdformatrc`, so when a
  project has them, setup converts them into `[lint]` and `[fmt]` sections of
  `gdsuite.toml` (with `gdtidy migrate`), so their settings are not lost. The
  original files are left in place; delete them once you no longer need
  gdlint or gdformat.

## What `migrate` does

`gdsuite migrate` brings a project to the current format, in one file:

- rewrites `gdsuite.toml`'s own sections and removes sections from gdsuite 0.1;
- keeps the tool sections already in `gdsuite.toml`;
- moves `gdtest.toml` into `[test]`, `gdhealth.toml` into `[health]` and
  `gdtidy.toml` into `[lint]` and `[fmt]`, with their comments, then deletes
  them. A file whose section `gdsuite.toml` already has stays where it is, and
  migrate warns that it is ignored;
- converts `gdlintrc` and `gdformatrc`, as setup does.

Review the result with `git diff` before committing.

## When to keep a tool file

A tool file is the right choice when the project uses that tool without
gdsuite. It also works in a gdsuite project, as long as `gdsuite.toml` has no
section for the same tool: each tool's settings belong in one file.
