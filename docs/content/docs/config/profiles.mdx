title: Profiles
description: "Historical note: named profiles are not the intended way to shape `gdsuite check`."
---

This page exists to record a rejected direction, not an active `check` contract.

`gdsuite check` should not derive its meaning from named profiles such as
`local`, `ci`, or `strict`. The RFC direction for the command is a fixed fast
static gate with explicit boundaries around `test` and `health`.

## Why this page still exists

Older drafts explored profile-driven pipelines. That approach was rejected
because it made `check` less obvious and blurred the difference between fast
local validation and slower CI-oriented composition.

## What to do instead

- Use `gdsuite check` for the fixed fast static gate.
- Use `gdsuite test` and `gdsuite health` as separate depth commands.
- Use explicit CI scripts and `gdsuite report ci` when automation needs a
  machine-readable pipeline.

## Current status

Do not document or implement profile-shaped meanings for `gdsuite check` from
this page. Treat the profile model as historical context only.
