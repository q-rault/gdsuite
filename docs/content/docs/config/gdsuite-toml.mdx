---
title: gdsuite.toml
description: gdsuite's settings and each tool's section, in one file.
---

`gdsuite.toml` sits next to `project.godot`. `gdsuite init` writes it with
gdsuite's own sections; the tool sections are yours to add.

## gdsuite's sections

```toml
[project]
root = "."

[tools]
# Where each tool comes from: a release tag (the default), a crate,
# a local checkout ("../gdtest") or a git repository.
gdtest_source = "github:q-rault/gdtest@v0.2.1"
gdhealth_source = "github:q-rault/gdhealth@v0.3.0"
gdtypecheck_source = "github:q-rault/gdtypecheck@v0.2.1"
gdtidy_source = "github:q-rault/gdtidy@v0.2.0"

[commands]
default_test_target = "test/"
default_health_subcommand = "health"

[reports]
default = "text"
artifacts_dir = "reports/gdsuite"

[check]
steps = ["fmt", "lint", "typecheck", "health"]
```

For `gdsuite check`, `gdsuite test` and `gdsuite health`, the file is
optional: without it, these defaults apply. The local toolchain still has to
exist, so run `gdsuite setup` first.

## Tool sections

Each tool reads its section itself, with the keys of its own config file. A
section you leave out means the tool's defaults (or its own file, see below).

```toml
# gdtest: the keys of gdtest.toml; profiles go under [test.profile.<name>].
[test]
exclude = ["test/helpers/**", "test/manual/**"]
timeout = 15000

[test.profile.ci]
reporter = "junit"
fail_fast = true

# gdhealth: the sections of gdhealth.toml, under [health].
[health.groups]
gameplay = ["gameplay/**"]
net = ["net/**"]

[health.thresholds]
cyclomatic_warn = 12

# gdtidy: the same [lint] and [fmt] as gdtidy.toml.
[lint]
disable = ["max-public-methods"]

[lint.rules.max-line-length]
max = 130

[fmt]
dict-brace-spaces = false
```

The reference for each tool's keys is in its own docs:
[gdtest](https://github.com/q-rault/gdtest#configuration),
[gdhealth](https://github.com/q-rault/gdhealth#configuration) and
[gdtidy](https://github.com/q-rault/gdtidy#configuration).

## One file per tool

A tool looks for its settings in its usual place (the project root, or the
folder it runs in), and there:

1. a section in `gdsuite.toml` comes first;
2. otherwise its own file (`gdtest.toml`, `gdhealth.toml`, `gdtidy.toml`);
3. otherwise its built-in defaults.

We do not recommend mixing the two. When `gdsuite.toml` has a tool's section,
the tool's own file is ignored, with a warning, and nothing from it is merged
in. Choose one place for each tool; `gdsuite migrate` moves tool files into
`gdsuite.toml`.

## Sections from gdsuite 0.1

gdsuite 0.1 had `[lint]` (`line_length`, `include`), `[health]` (`command`,
`fail_on`, `bundle_dir`), `[gdtest]`, `[gdhealth]`, `[typecheck]` and `[fix]`
sections with another meaning. gdsuite rejects them with a pointer to
`gdsuite migrate`, which removes them.
